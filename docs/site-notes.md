# ETC利用照会サービス — サイト調査メモ(§2)

2026-11-18、Claude in Chromeでユーザーの実アカウントにログインした状態を一緒に確認しながら調査。
**ここに書く実データの値(カード番号・車両番号)はすべてマスク済み。** 生の値はチャット・ファイルのどちらにも残していない。

## 画面遷移・URL構造

- ベースURL: `https://www2.etc-meisai.jp/etc/R`
- 画面遷移はすべて `funccode` / `nextfunc` などのクエリパラメータで制御される、関数コード方式(古い日本の業務システムによくある構成)。**ログイン前のログインフォームとログイン後の利用明細トップは同一URL** (`?funccode=1013000000&nextfunc=1013000000`)。サーバー側のセッション状態によって返すHTMLが変わるだけなので、**URLではログイン判定できない**。DOM内容で判定する必要がある(後述)。
- 月を指定して表示: `?funccode=1013000000&nextfunc=1013200000&taisyoYM=YYYYMM` (例 `taisyoYM=202610`)。
  - ただし **この `taisyoYM` は、既に実行済みの検索結果の中から表示月を切り替えるだけ**。検索結果自体の範囲(＝CSV出力される範囲)は変えない。実際に試したところ、月タブを切り替えてから「明細CSV」を出力しても、直前に出力したCSVとバイト単位で同一だった。
  - **範囲を変えるには「検索条件の指定」画面(`nextfunc=1014000000`)で日付を入力し、「検索」を実行し直す必要がある。**
- 全頁選択: `?funccode=1013000000&nextfunc=1013300000&selectKbn=ALLON` — 現在の検索結果の全ページ・全行を選択状態にする。注意書きに明記: **「全頁選択」を選択した後に「月選択」「頁選択」をしても全頁選択は解除されない**(=一度ONにすればそのまま複数月をまたいでCSV/PDF出力に使える)。

## ログイン判定(content script `site-detect.ts` 用)

- ログイン前: ユーザーID入力欄・パスワード入力欄(`password`系input)を含むフォームが表示される。
- ログイン後: 上部ナビに `利用明細の表示 / 検索条件の指定 / ユーザー情報変更 / カードの追加登録／削除 / サービスのご解約 / ログアウト` の6項目が並ぶ。この文字列(特に「ログアウト」「利用明細の表示」)の有無で判定するのが確実。
- **重要な追加発見**: ブラウザの「戻る」操作・30分以上前に開いた画面への再アクセス・お気に入り登録からの直接アクセス・複数タブでの交互操作、のいずれかを行うと、ログインもしていないのに専用のエラー画面が出る。
  - 画面タイトル: `利用明細 -確認してください-`
  - 本文: 「以下のような操作により、処理が受け付けられませんでした。」+ 理由の箇条書き + 「利用明細へ」ボタン(押すと `利用明細の表示` に戻れる、**再ログイン不要**)
  - これは「セッション切れ」ではなく「画面遷移の整合性ガード」であり、content script側ではログイン画面とは別の状態として検出し、「利用明細へ」に相当するボタンを押すだけで復帰できるようにする必要がある。
  - **実際のセッションタイムアウトは「直前の画面を開いてから30分」**という記載を確認(実際にタイムアウトさせての確認はしていない)。タイムアウト後に本当にログアウト扱いになるのか、同じ画面が出るだけなのかは未確認。

## 検索条件の指定画面(`nextfunc=1014000000`)の項目

| 項目 | 内容 |
|---|---|
| 利用年月日 | from/to を年・月・日の別々のセレクトボックスで指定。**初期値は「今日から過去15ヶ月」**(例: 今日2026/11/18なら2025/08/19〜2026/11/18)。 |
| (件数上限の注意) | 表示対象のETCカードが100枚を超える場合のみ、連続2ヶ月以内に制限。1〜数枚のカードなら15ヶ月を一括指定できる。 |
| 走行区分 | 全て / ETC無線走行のみ / ETCカード手渡しのみ(ラジオボタン) |
| 車両番号(ナンバー下4桁) | 走行区分が「ETC無線走行のみ」のときだけ、特定の車両に絞り込み可能 |
| 月の区切り日 | 月末 or 01〜31日。デフォルト「月末」。20日区切りなどカスタム可(「前月21日〜当月20日」のように月の集計単位がずれる)。 |
| 1ページの表示件数 | 指定なし(1000件単位)/ 指定あり(10〜1000件を10件単位) |
| 表示対象のETCカード番号 | 登録カードがマスク表示される(複数枚あれば選択可能と思われる、今回は1枚のみで未確認) |

→ **sync-runner の実装方針**: 1か月ずつ取得するなら、この検索フォームに「その月の1日〜月末(またはユーザー設定区切り日)」を明示的にセットして検索を実行し直してから、全頁選択→CSV、という手順を踏む必要がある。`taisyoYM` だけでは不十分。

## CSV出力の実際の挙動

- 「明細CSV」リンクをクリックすると、新しいタブが一瞬開いてすぐ閉じ、OSの通常のファイルダウンロードとして保存される(`~/Downloads/` に保存されるタイプの挙動)。**ページ内に結果が表示されるわけではない。**
- ダウンロードされるファイル名は **`YYYYMMDDHHmm.csv`**(エクスポートを実行した日時。例: `202611180227.csv` = 2026/11/18 02:27に出力)。
- **文字コードはShift_JISで確定**(§2の見込み通り)。
- リンクのhref/onclickの実値(セッション依存のパラメータを含む可能性が高い)は、ブラウザ操作ツールの安全機構により取得できなかった(cookie/query string相当として自動ブロックされた)。これは意図された安全策であり、無理に回避していない。
  - **content script側の実装方針**: 明細CSVの `<a>` 要素を実行時に`document`から探して `.href` を読み取り、`fetch(href, { credentials: 'include' })` で直接取得する(§3.2 プランA通り)。URLを決め打ちしない。毎回DOMから拾うことで、セッション依存のパラメータが変わっても追従できる。
  - **`<a>` 要素をクリックしてはいけない**: クリックすると新規タブ経由でOSのファイルダウンロードが走ってしまい、バックグラウンド同期のUXとして不適切(ユーザーのダウンロードフォルダに同期のたびにファイルが増えてしまう)。必ず `fetch` で中身を取得し、画面上はダウンロードを発生させないこと。

## CSVの列構成(確定)

ヘッダー行(Shift_JIS、カンマ区切り、全角文字含む):

```
利用年月日（自）,時分（自）,利用年月日（至）,時分（至）,利用ＩＣ（自）,利用ＩＣ（至）,割引前料金,ＥＴＣ割引額,通行料金,還元額適用料金,後納料金,車種,車両番号,ＥＴＣカード番号,備考
```

| 列 | 例 | 備考 |
|---|---|---|
| 利用年月日（自） | `26/04/11` | `YY/MM/DD`。2桁年(2000年代前提で20xxとみなす)。 |
| 時分（自） | `14:32` | `HH:MM` |
| 利用年月日（至）/ 時分（至） | 同上 | 出口の日時。**日をまたぐ場合もある**(例: 23:17入 → 翌日00:31出)。 |
| 利用ＩＣ（自） | `堺` / 空欄 | **空欄になることがある**(入口不明/手渡し等)。型は`entryName?: string`のままでよい。表記に「入」「出」「本線」「JCT」等の接尾辞が付くことがある(例: `松原（本線）入`, `東大阪ＪＣＴ`) → `normalize-ic.ts` の正規化対象。 |
| 利用ＩＣ（至） | `長原` | 空欄は未観測(出口は必須っぽい)。 |
| 割引前料金 | 空欄 or `1730` | **割引が無い行は空欄**(0ではない)。割引がある行だけ値が入る。 |
| ＥＴＣ割引額 | 空欄 or `-520` | 割引額はマイナス値。 |
| 通行料金 | `630` | 実際の通行料金(割引後)。 |
| 還元額適用料金 | `0` | ETC2.0還元等。翌々日以降に反映される旨の注意書きあり、当日〜翌日分は0のまま変動する可能性。 |
| 後納料金 | `630` | 最終的な請求額。**`Trip.fare` にはこれを使う**(通行料金と基本一致するが、将来の仕様変更に備えて後納料金を優先)。 |
| 車種 | `1` | 数値コード。今回のサンプルは常に`1`で、他の値は未確認。公式のコード表は未確認なので**決め打ちでマッピングしない**(`vehicleClass`は`raw`から読める生の値を暫定表示にとどめる)。 |
| 車両番号 | (マスク対象) | **実際の値は4桁未満の小さい数字**(例: 3桁・4桁)で、ナンバープレートの下4桁や社内管理用の短い識別子のような値だった。車両を乗り換えると値が変わる(同一カードで複数の値が時系列で出現するのを確認)。仕様書通り**保存しない**(Trip型に車両番号フィールドは持たせない)。 |
| ＥＴＣカード番号 | `********xxxx` | **サイト側が既に先頭を`*`でマスクして返してくる**。末尾4桁だけ読み取って`cardLast4`に保存すればよい。 |
| 備考 | `確定` / `確認中` / `確定;深夜割引` | **ステータスと割引種別が同じ列にセミコロン区切りで入る**。`確認中`→`確定`に変わるまで最長3週間かかる旨の案内あり。割引種別はこれまでに `休日割引` `深夜割引` `ＥＴＣ通常` `短距離区間利用割引` `大阪都心流入割引` を確認(ETC運営者・路線ごとに種類が増える可能性があるため、固定リストでバリデーションしない)。 |

### 備考欄のパース方針

`備考` を `;` で分割し、先頭が `確定` または `確認中` ならステータス、残りがあれば割引ラベルとして扱う(例: `確定;深夜割引` → `status: 'confirmed', discount: '深夜割引'`)。

### 距離について

CSVに距離(km)の列は**存在しない**。§5で想定していた通り、距離・平均速度はIC座標とルート計算から推定するほかなく、CSVからは導出できないことが確定した。

### 道路名について(新たな制約)

**CSVに道路名(高速道路名)の列は存在しない。** 列は上記15列のみで、`Trip.road` に相当するデータは入っていない。IC名(`利用ＩＣ（自）`/`利用ＩＣ（至）`)から道路名を知るには、距離推定と同様にIC名→路線名の対応表を別途用意する必要がある(§5のIC座標整備と合わせて検討するのが効率的)。それまでは「利用道路」ランキングやRecordsの「道路」列は空欄 or 不明表示になる前提で実装する。
